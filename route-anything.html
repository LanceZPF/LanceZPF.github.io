Route Anything

No single model, skill, block, or computation path is best at everything — so the interesting question is never which one, but who decides, at what granularity, and with what feedback. This thread runs that same question down the whole stack: from routing across frontier LLMs in an agent loop, all the way down to routing individual attention computations inside a single denoising step.

L0 agentic routing → which LLM runs this task
Agent-as-a-Router: Agentic Model Routing for Coding Tasksfirst agentic routing
Under Review · 2026 · ★ 1K+ on GitHub

Prior routers treat model selection as a static, one-off classification problem, and their real weakness is an information gap: simply handing a plain LLM router task-dimension performance statistics already buys a 15.3% relative gain over a heuristic router with the same priors. Agent-as-a-Router instead recasts routing as a Context → Action → Feedback loop that accumulates execution-grounded experience while deployed. The concrete system, ACRouter, pairs an Orchestrator, a Verifier, and a Memory module; CodeRouterBench supplies roughly 10K task instances scored across 8 frontier LLMs so routers can be compared by cumulative regret on streaming tasks rather than one-shot accuracy.

picked up by The startup project OpenSquilla builds on this line of work in Agentic Routing: The Harness-Native Data Flywheel, which cites Agent-as-a-Router while pushing routing down to the harness state of each agent step.

L1 model level → which VLM, at what cost
SCOPE-Router: Cost-Aware Open-Set VLM Routing for Execution-Oriented Tasks
arXiv 2608.12127 · 2026

Vision-language routing had been confined to conventional VQA evaluation, uncalibrated for open-set conditions, and trained with objectives that dilute multi-positive signals through softmax normalization while ignoring price entirely. VLM-ExecRouterBench is the first execution-oriented VLM routing benchmark, spanning Code, Agentic, and Search domains over 11 candidates whose costs differ by nearly two orders of magnitude. SCOPE-Router is a dual-tower router that matches queries against model behavior profiles built by hybrid calibration (random, diagnostic, and diversity sampling), so a newly added model can be routed to without any retraining. Its architecture-agnostic objective, CRM+RCCR, folds cost preference into continuous relevance targets via per-pair independent scoring — +1.84 Rank Score out-of-distribution, +6.75 under doubly-OOD open-set evaluation.

L2 skill level → which tools an agent reaches for
SkillDAG: Self-Evolving Typed Skill Graphs for LLM Skill Selection at Scale
arXiv 2606.03056 · 2026

Once a skill library grows large enough, picking the right skill stops being a similarity problem and becomes a structural one: skills depend on, conflict with, specialize, and duplicate one another, and neither exhaustive listing nor vector search captures those relations. SkillDAG encodes them as a typed directed graph handed to the agent as a callable retrieval interface at inference time rather than frozen inside a static pipeline — every query returns vector matches, typed-edge neighbors, and conflict signals together. A propose-then-commit protocol lets the agent write back edges that real execution validated, so the routing structure compounds across episodes instead of decaying. Ranking holds as the candidate pool grows tenfold, where fixed seeding-diffusion pipelines fall off.

L3 block level → which submodel runs this frame
Efficient Video Object Segmentation and Tracking with Recurrent Dynamic Submodel
CVPR 2026

Here the router moves inside the network. Recurrent Dynamic Submodel (RDS) uses a prediction-aware router that exploits temporal priors — consecutive video frames rarely need the same capacity — to activate a different submodel per frame, and pairs it with Importance-aware LoRA so the accuracy-speed trade-off is reached with minimal trainable parameters and minimal training data.

L4 timestep-wise → three granularities at once
RAPID³: Tri-Level Reinforced Acceleration Policies for Diffusion Transformer
ICLR 2026

The finest rung, and the only one that routes at several granularities simultaneously. Training-free diffusion accelerators normally apply one uniform heuristic to every image, while per-image dynamic networks demand expensive fine-tuning. RAPID³ keeps the generator completely frozen and instead attaches three lightweight policy heads. At every denoising timestep all three inspect the current state and independently decide their own speed-up, so the compute path is re-routed continuously as the sample evolves:

tri-level policy — one decision per head, per timestep
TIER 1step
Step-Skip
The coarsest cut: decide whether this denoising step is needed at all, and drop it wholesale when the current state says the trajectory can afford it. Routing over time.
TIER 2feature
Cache-Reuse
If the step does run, decide per block whether to recompute features or replay the cached ones from an earlier timestep. Routing over depth.
TIER 3token
Sparse-Attention
Inside whatever is actually recomputed, decide how much of the attention map is worth evaluating and restrict it to a sparse subset. Routing over tokens.

All policy parameters are learned online with Group Relative Policy Optimization (GRPO), and an adversarially learned discriminator augments the reward so returns only rise for samples that stay near the original model's distribution — which is what stops the policies from reward-hacking their way into fast but degenerate outputs. Across Stable Diffusion 3 and FLUX this reaches nearly 3× faster sampling at competitive quality, with zero updates to the base generator.
